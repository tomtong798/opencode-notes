# 服务访问凭证详解（server basic auth × HMAC 会话 × 配对码——本机门禁三件套）

> 一句话：**桌面/CLI/浏览器连本机 opencode server 的认证三件套——启动生成的 32 字节密码（basic auth）、HMAC 双层签名的 30 天会话 token（密码轮换即全部失效）、5 分钟 TTL 的一次性配对码（`opencode pair` 握手）；与 LLM 凭证体系零代码耦合（server/auth.ts 对 credential/integration 零 import）。**

## 0.5 通俗完整描述（先读这段再看细节）

opencode server 跑在你机器上，谁能让它干活？**三件套各管一段**：

**密码（长期钥匙）**：standalone 模式启动时随机生成 32 字节，客户端每个请求带 `Authorization: Basic opencode:<password>`。落 `service.json`（文件权限 0600），CLI 的 `opencode service get password` 读的就是它。

**会话 token（免重复验证）**：30 天 TTL 的 HMAC 签名 token——签名的密钥从密码派生（**改密码 = 所有会话立即失效**，一行注释明说）。配对会话 token 与密码本体等价有效（`authorized` 两者都收）。

**配对码（首次握手）**：`opencode pair` 生成 5 分钟 TTL 的一次性 code；浏览器/远程客户端访问 `server.connect` 端点用 code **换**会话 token——code 只能用一次（Cache.invalidateWhen 原子核销），过期/已用提示"Run opencode pair to get a new one"。UI 上对应扫码/粘贴配对链接的流程（QR 码里就是 {"code","urls"} JSON）。

安全设计三处精细（都有注释背书）：比较用 `timingSafeEqual`（防时序攻击）；cookie 名带端口（"Browsers share cookies across ports on the same host"）；签名密钥派生而非存副本。为什么这么简单：威胁模型是**同机其他本地进程**，不是互联网。

一句话：**密码管长期、token 管便捷、配对码管首次——本机门禁三件套，与 LLM 凭证无关**。

## 1. 密码与会话（server/auth.ts，66 行）

桌面/CLI 连 server 的 password 在 **server + cli 两层，与 LLM 凭证体系完全无关**：

- **server 侧**（server/src/auth.ts，66 行）：HTTP basic auth，username 固定 `opencode`（:25）；`authorized` 接受 password 本体**或**配对会话 token（:36-38）。会话是 HMAC 双层签名：`sign() = HMAC(HMAC(password, "opencode-session-v1"), expires)`，30 天 TTL（:27、:64-67）；"Sessions are signed with a key derived from the server password, so rotating the password revokes every session"（:41 注释）；比较用 `timingSafeEqual`（:61）；cookie 名带端口——"Browsers share cookies across ports on the same host"（:49-53）。
- **CLI 侧**（cli/src/services/）：standalone 模式 `randomBytes(32).toString("base64url")` 生成密码（standalone.ts:37），经 `OPENCODE_PASSWORD` env 传给 server 子进程（:17-24），客户端以 basic auth 回连（:53）。服务注册/配置落 `service.json`（`mode: 0o600`，service-config.ts:97-100；端口按 channel 派生，0xC0DE 致敬 v1，:65-77）。`dev:live` 用的 `opencode service get password` 即读此文件（handlers/service/get.ts:8-13）；显式 `--server` 时密码来自 `Env.password`（server-connection.ts:24-25、env.ts:7-10）。

## 2. 配对码（server/pairing.ts，44 行 + handlers/server.ts）

**发放**：`opencode pair` 命令 → `server.pair` 端点 → `pairing.issue()`（handlers/server.ts:29）——`randomBytes(16)` 转 base64url，进容量 1000、TTL 5 分钟的 Cache（pairing.ts:22-27）。

**核销**（换 token 的一次性闸门）：`server.connect` 端点（handlers/server.ts:31-47）：

```
POST /server/connect {code}
│
├─ pairing.consume(code)（:36）
│   └ Cache.invalidateWhen —— ★原子核销：删成功=true（只能用一次）；
│      注释明示 "lookup never runs"（:18——只走 set/invalidateWhen，
│      防并发双花）
│
├─ true → ServerAuth.issueSession(auth)（:36，auth.ts:40）
│   └ 返回 30 天会话 token
│   ├─ API 客户端（Accept 非 HTML）→ JSON {token}
│   └─ 浏览器导航（text/html）→ 302 重定向 / 并种会话 cookie（:45-47）
│
└─ false → 401："pairing link expired or was already used.
              Run `opencode pair` to get a new one."
```

**客户端侧**（app/src/servers/connect/scanner.tsx:36-39）：扫 QR 码得 `{"code","urls"}` JSON，`pairingLink()` 解出 code 走 connect——桌面"扫码连服务器"的背后就是这套。

## 3. 不变量

1. **一次性核销是原子的**：Cache.invalidateWhen（同款机制见 16_pty 的票据核销）——两个客户端同时拿同一 code，只有一个成功。
2. **密码轮换杀全部会话**：会话签名密钥 = HMAC(password, …) 派生，密码变则旧 token 全部验证失败。
3. **与 LLM 凭证零交集**：本篇全部代码（auth.ts/pairing.ts/standalone.ts）不 import credential/integration——第三把钥匙的独立性是代码事实。
