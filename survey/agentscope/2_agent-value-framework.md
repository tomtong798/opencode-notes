## 1. 结论先行

> **同质化是真的，但它只发生在"内核层"。用户从来不为内核付费。**
> 内核同质化就像 2015 年 Web 框架都长成 MVC + ORM 一样，是行业成熟的标志而非危机。

模型的智力被所有产品平等地共享（同一家的 API 大家都能调），所以**模型能力本身不构成任何 agent 的差异化**。差异化只存在于模型够不到的地方。

## 2. 四层市场模型

```
┌─────────────────────────────────────────┐
│  产品/工作流层   ← 差异化在这里          │
│  (谁拥有任务、谁拥有数据、谁拥有信任)     │
├─────────────────────────────────────────┤
│  运行时层        ← 部分差异化            │
│  (上下文工程、可靠性、恢复、集成深度)     │
├─────────────────────────────────────────┤
│  内核层          ← 已完全同质化          │
│  (agent loop、tool calling、MCP、流式)   │
├─────────────────────────────────────────┤
│  模型层          ← 每次发布向下吞噬      │
└─────────────────────────────────────────┘
```

关键动力学：**模型层每次升级，都向下吞噬一层的价值**。

- 两年前"让模型分步思考"的 prompt 技巧 → 现在内置在 reasoning model 里；
- 去年"多轮工具循环编排"的精巧逻辑 → 现在模型自己就会。

所以任何把价值押在"我比别人的循环写得聪明"上的产品，都在赌一个每六个月归零一次的资产。

## 3. Swap 测试：第一块试金石

> **Swap 测试：把底层模型换掉，这个产品还剩什么？剩得越多，价值越大。**

按这个标准：

- 纯 chat 套壳（换 system prompt 的 GPT wrapper）剩零 → 最先死；
- OpenCode 换掉模型照样是 OpenCode，AgentScope 换掉模型照样是 AgentScope → 它们的价值在别处。

## 4. 价值的五个藏身之处（按抗吞噬能力排序）

### ① 上下文工程 —— 抗吞噬能力最强

同样的模型 + 同样的工具，不同的上下文 = 不同的结果。Agent 产出质量 ≈ 模型在每个决策点看到的东西的质量。这是当前性价比最高的差异化点。

- **OpenCode**：`session/compaction.ts`（历史压缩）、文件快照、worktree 感知、`.opencode/skills` 按仓库定制指令（"这个仓库测试不能从根目录跑"这类知识）。
- **AgentScope**：`InjectionConfig`（动态注入）、`AgenticMemoryMiddleware`（跨会话事实）、`RAGMiddleware`。

注意：上下文窗口变大**不会**杀死这一层——垃圾上下文塞进 10M 窗口还是垃圾，检索和取舍的质量永远是工程问题。

### ② 拥有结果，而不是拥有对话

聊天 agent 的终点是"回答了"；有价值的 agent 终点是"**任务完成了，且失败时你知道怎么办**"。

- OpenCode 把每一步事件溯源落盘（`session.inbox.enqueued → delivered`、execution claim 崩溃恢复）——进程被杀掉，会话还能接着跑。**可靠性是 demo 不出来、但企业付费的唯一理由**。
- AgentScope 的 `GoalPipeline`（executor/verifier 循环）是同一思路的另一种形态：自带验收的执行。

### ③ 反馈闭环 —— 用得越多越好

接受率、编辑保留率、报错→修复轨迹。在特定领域积累的这些数据，模型厂商拿不到。这是吞噬顺序里最靠后的资产。

### ④ 集成深度与分发

**Agent 的价值 = 它嵌入工作流的位置。** 换供应商成本来自集成，不来自智力。

- AgentScope：Channel（飞书/钉钉/Discord）是明牌——企业 IM 即分发。
- OpenCode：TUI/Desktop/Web 多端 + PTY + Git/worktree 深度集成。

### ⑤ 信任边界

权限引擎、审计、沙箱（AgentScope 的 Docker/K8s/E2B workspace）、合规。B2B 的钱在这里。

## 5. 用框架回看 OpenCode 与 AgentScope

| | 内核（同质化部分） | 真正的价值主张 |
|---|---|---|
| **OpenCode** | agent loop、tool calling | **拥有终端里的编码工作流**：事件溯源的可靠会话 + Git/worktree 深度集成 + 按仓库定制的 skills + 多端一致体验 |
| **AgentScope** | agent loop、tool calling | **拥有构建和部署 agent 的平台**：编排原语 + 沙箱舰队 + 企业渠道 + 语音/A2A + 中间件扩展面 |

佐证：AgentScope README 明确写着 "*We design for increasingly agentic LLMs... rather than constraining them with strict prompts*"——连框架作者都选择"脚手架做薄，把智力让给模型"。这反过来逼着价值落在平台服务（渠道、沙箱、记忆）上，而不是循环逻辑上。

## 6. 可操作的判断清单

评估任何一个 agent（产品或框架）时问五个问题：

1. **Swap 测试**：换掉底层模型，它还剩什么？
2. **结果测试**：它交付的是回答还是完成的任务？失败时用户损失多大？
3. **数据测试**：使用它会产生只有它自己能受益的数据吗？
4. **位置测试**：它嵌在工作流的哪个位置？拔掉它疼不疼？
5. **失败测试**：出错了能不能恢复/审计/重放？

五个都答不上来的，就是同质化大海里的一滴水——也正是"感觉市面上的 agent 都差不多"时，被感觉到的那部分。

---

> 一句话收尾：**模型负责越来越聪明，agent 的一切其他属性负责越来越可信、越来越嵌入、越来越懂你的具体领域。同质化的只是前者已经解决掉的部分。**
