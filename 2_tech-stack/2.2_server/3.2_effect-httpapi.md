# @effect/platform HttpApi

## 是什么

Effect 官方的**声明式 HTTP API 层**：用 Effect Schema 定义端点（路径、方法、请求体、响应、错误），组装成 Group（`HttpApiGroup`）与 API 树（`HttpApi`）。

- 服务端：实现 handler，错误类型自动映射 HTTP 状态码（`@httpApiStatus` 注解）
- 消费端：从同一 API 定义获得全类型化调用

## 业界类比

- tRPC 的类型安全 + Spring 注解式声明的合体，但跑在 Effect 上
- 对比 OpenAPI：契约即 TS 代码（不是 YAML），编译期就校验一致性

## 在 OpenCode 中的角色

- **protocol 包**用它定义 ~30 个 API Group（Server、Location 作用域的 Agent/Model/Provider/MCP/FileSystem…、Session 组、Event 组）
- 中间件：Authorization（鉴权）+ SchemaError（错误整形）；客户端侧另有 Location/SessionLocation 中间件
- **server 包**实现 handlers（28 个 handler 模块合并）
- 端点清单有客户端差异：`promiseOmitEndpoints`（排除 pty 流式端点）与 `effectOmitEndpoints`
- **铁律**：改了 Protocol/Server 的 HttpApi 后必须在 `packages/client` 跑 `bun run generate`（见 [httpapi-codegen.md](10_httpapi-codegen.md)）

## 与其他技术的关系

- **Effect Schema**：端点形状的底层（见 [effect-schema.md](3.1_effect-schema.md)）
- **SSE**：`groups/event.ts` 的 `event.subscribe` 用 `StreamSse` 编码事件流端点（见 [sse.md](7_sse.md)）
- **effect/cli**：命令行与 HTTP API 同属 Effect 服务端工具族
