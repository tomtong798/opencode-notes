# Effect Schema

## 是什么

"一次定义，三处受益"的 schema 库：同一份声明式定义（`Schema.Struct({ ... })`）同时产出：

1. **静态 TS 类型**（推导，无需手写 interface）
2. **运行时校验器**（decode/encode，未知数据在边界处校验一次）
3. **JSON Schema**（供 LLM 工具定义等消费）

类比：*Zod 的 Effect 原生版*；仓库风格还偏好 `Schema.UnknownFromJsonString`、`Schema.decodeUnknownOption` 等组合子替代手写 `JSON.parse` + try/catch。

## 业界类比

- Zod / Joi / Pydantic 的 Effect 系对应物
- "边界校验一次，内部传递已验证类型"范式的载体（根 AGENTS.md 明文要求）

## 在 OpenCode 中的角色

- **全部契约的单一真相源**（`packages/schema`，79 个领域文件）：
  - 公共领域形状与 durable 事件 payload（Session、Agent、Model、Permission、Mcp…）
  - Protocol 的 HttpApi 请求/响应/错误定义
  - 工具的 input/output schema（见 `specs/v2/tools.md`）
- 事件系统基础：`durable()` / `ephemeral()` 事件定义、事件清单（`event-manifest.ts` 的 `ServerDefinitions` 对外 / `Definitions` 对内）
- 分层铁律的起点：Schema → Core → Protocol → Server（见 [layered-monorepo](../2.6_architecture-styles/4_layered-monorepo.md)）

## 与其他技术的关系

- **HttpApi**：端点定义的 schema 层（见 [effect-httpapi.md](3.2_effect-httpapi.md)）
- **httpapi-codegen**：读 Schema 契约生成客户端（见 [httpapi-codegen.md](10_httpapi-codegen.md)）
- **Zod/Standard Schema**：工具契约同时接受 Standard Schema V1 与 Standard JSON Schema V1（`Tool.make`），Effect codec 保留原生方向
- **Drizzle**：Schema 管契约，Drizzle 管表结构（两套系统，各司其职）
